    Completed: Release 0.25.0 (0093-0095 performance wave + 0097-0099 Wan consistency wave)¶

    Metadata¶

    • Created: 2026-07-25
    • Status: Completed
    • Completed: 2026-07-25 — v0.25.0 tagged from 2452f0c, workflow 30162410505 green on all four jobs (tests, lint-build, PyPI trusted publishing, GitHub Release), PyPI + GitHub Release verified with wheel + sdist

    ADR status¶

    • Governing ADRs: ADR 0001 (smoke evidence for changed routes), ADR 0002
    • ADR impact: None (release execution; the shipped items carry the design decisions)

    Context¶

    Two reviewed waves ship together. The performance wave (0093 sequential weight prefetch, 0094 default MLX buffer-cache limit, 0095 flux2 prompt/compile caches) was committed on main as 9c1c59a and sat UNRELEASED. The Wan consistency wave (0097 --last-image EXPERIMENTAL bracket conditioning, 0098 prompt-truncation warning, 0099 explicit denoising step grids) completed a three-cycle adversarial review (cycle-3 verdict GREEN: 1517 passed / 7 skipped, lint clean) and sits in the working tree on b71bc4b. The owner explicitly ordered the release. The BlackPixel host adoption of the new surfaces is gated on this release.

    Problem¶

    0093/0094 touch EVERY family's weight-load path and 0098 rewrites the Wan prompt-encode measurement path; ADR 0001 discipline requires one real same-seed output-identity check against the previous release before the release claims "no output change".

    What we want to do¶

    Cut 0.25.0 through the standard release flow (docs/release.md tag path) with smoke evidence recorded here.

    Requirements (release checklist, from the cycle-3 gate)¶

    1. Version bump pyproject.toml 0.24.0 -> 0.25.0 (minor: additive features) + uv lock regeneration + uv lock --check.
    2. CHANGELOG: retitle [Unreleased] -> [0.25.0] - 2026-07-25 (the heading date is load-bearing for VersionUtil._scan_changelog_release_date), add a release-summary intro in the 0.24.0 style, fold the superseded "Backlog: filed 0093/0094/0095" paragraph, preserve the --last-image EXPERIMENTAL framing verbatim, mention capabilities schema_version 4 -> 5.
    3. VersionUtil.PACKAGED_RELEASE_DATE -> 2026-07-25 + rerun tests/utils/test_version_util.py.
    4. Regenerate llms.txt / llms-full.txt with the full 0.25.0 surface (--last-image + supports_last_image, --denoising-step-list, truncation warning + prompt_tokens/prompt_truncated, weight prefetch + MFLUX_NO_WEIGHT_PREFETCH, default cache-limit ladder + MFLUX_MLX_CACHE_LIMIT_GB + -1 opt-out, flux2 prompt/compile caches).
    5. Smoke: one short TI2V-5B same-seed 0.24.0-vs-0.25.0 comparison (0091 recipe: q8, 384x384, 9 frames, 2 steps, seed 42; baseline from a v0.24.0 worktree with identical locked deps; raw-YUV comparison; bitwise identity expected).
    6. Gates: make lint; full fast suite (expect 1517+ passed / 7 skipped); uv build + twine check.
    7. Single release commit ("Release 0.25.0"), push main, tag v0.25.0, push tag, watch the release workflow (tests -> lint-build -> PyPI trusted publishing -> GitHub Release), verify PyPI wheel+sdist and GitHub Release assets.
    8. Post-release hygiene: move 0093/0094/0095/0097/0098/0099 and this item to completed/ with evidence links; update the overview ledger and counts; one hygiene commit + push.

    Scope¶

    Release execution only.

    Non-goals¶

    New features; changing defaults beyond what the two waves shipped; the 0099 grid-honest Lightning-vs-base chain A/B (stays open in the 0099 item); the 0097 broader-recipe probes (bounds recorded in the 0097 item).

    Dependencies and related tasks¶

    • 0093, 0094, 0095 (committed 9c1c59a), 0097, 0098, 0099 (working-tree wave) — this releases them.
    • BlackPixel adoption of --last-image, --denoising-step-list, truncation metadata, and the cache/prefetch env surface consumes this release.

    Expected outcomes¶

    0.25.0 on PyPI with smoke evidence; BlackPixel unblocked to bump its pin.

    Smoke evidence (recorded 2026-07-25, TI2V-5B q8, 384x384, 9 frames, 2 steps, seed 42)¶

    • Baseline: v0.24.0 worktree at 2b496bf (git worktree add --detach, uv sync --frozen), dependency set IDENTICAL to the release tree (the 0.25.0 lock diff is the package version line only). Candidate: the full 0.25.0 release tree. Both runs used mlxgen generate --model AbstractFramework/wan2.2-ti2v-5b-diffusers-8bit --prompt "a red ball rolling across a wooden table" --width 384 --height 384 --frames 9 --steps 2 --seed 42 --no-prompt-cache so both exercised the full UMT5 encode path (0098 rewrote its measurement path) instead of the shared prompt-embed disk cache.
    • Verdict: raw-YUV comparison (the preserved /tmp/compare_videos.py from the 0.24.0 release) reports frames=9 max_abs_yuv_diff=0 — BITWISE IDENTICAL. This covers the 0093 prefetch load path (bytes identical by design), the 0094 default cache limit (buffer-cache bookkeeping only), and the 0098 encode-path rewrite (token counting must not change embeds).
    • Observed live: the candidate announced the 0094 default exactly as documented ("Applying default MLX cache limit: 8.0 GiB (total RAM / 8, clamped to [1, 8] GiB)...") — one stderr line, override flags named.
    • Wall time: baseline 142 s, candidate 105 s end-to-end (second run benefits from page-cache warmth; not recorded as a measured 0093 speedup claim).
