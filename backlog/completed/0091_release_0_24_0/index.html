    Completed: Release 0.24.0 (both 2026-07-22/23 waves)¶

    Metadata¶

    • Created: 2026-07-22
    • Status: Completed
    • Completed: 2026-07-23 — v0.24.0 tagged from 2b496bf, workflow 29977218806 green (tests, lint, build, twine), PyPI + GitHub Release verified with wheel + sdist

    ADR status¶

    • Governing ADRs: ADR 0001 (smoke evidence for changed routes), ADR 0002
    • ADR impact: None (release execution; the 0086/0087 items carry the design decisions)

    Context¶

    Backlog 0086 (Wan UMT5 prompt-embed disk cache + residency + model_kwargs passthrough) and 0087 (--no-validate-health + enriched save events) are implemented and adversarially reviewed (three-cycle review, 2026-07-22) but sit UNCOMMITTED in the working tree with pyproject.toml still at 0.23.1. The BlackPixel host's warm video worker requests residency through model_kwargs and degrades gracefully on 0.23.1 — the dominant per-scene cost (UMT5 reload, tens of seconds + ~11 GB transient) stays live until this release ships and the host pin moves.

    Current code reality¶

    Working tree contains: src/mflux/models/wan/prompt_embed_store.py (new), wan2_2_ti2v.py encode-path rewrite (numpy tokenization + store + residency), python_runtime.py model_kwargs (+ cache_key coverage), wan_generate.py / seedvr2 CLI flags, runtime_events.py save-event enrichment, tests (store unit, efficiency, router, argparser, python_runtime), CHANGELOG [Unreleased], docs (api.md, python-integration.md, wan flags in the generate epilog). Full CI selection green: 1352 passed.

    Problem¶

    The change set rewrites the prompt-encode path of EVERY Wan route (tokenizer return_tensors change + default-ON disk cache) with mock-based tests only — ADR 0001's enforcement clause requires real-checkpoint smoke evidence before release claims.

    What we want to do¶

    Cut 0.24.0 through the standard release flow with the smoke evidence recorded.

    Requirements (release checklist, from the cycle-2 review)¶

    1. Real-checkpoint smoke evidence (small frame counts; A14B long runs need owner approval per AGENTS.md):
    2. (a) cache-miss embeds/output identical to 0.23.1 same-seed baseline;
    3. (b) disk-cache-hit run bit-identical to its own miss run;

    8. Regenerate llms.txt / llms-full.txt (currently mention none of the new flags).
    9. Gates: make lint / make check / make test-fast + full CI selection; commit; tag via GitHub Actions release workflow (never locally).
    10. Post-release: recurrent hygiene — move 0086/0087 (and this item) to completed/ with evidence links; notify the BlackPixel pin-bump item (blackpixel backlog 0064).

    Candidates to ride this wave (cycle-3 review, 2026-07-22)¶

    • Resolve None video params to MODEL-CONFIG defaults inside generate_video/generate_outputs (or export a ModelConfig.resolve_video_defaults() helper). Today only the CLI's _apply_model_defaults does this, so the BlackPixel worker had to mirror the param->config-key mapping (apply_wan_video_model_defaults) — a two-repo copy of the mapping table that strains the "defaults in one source of truth" rule. Landing it here lets the host delete its copy.

    Release-cut process hazard (cycle-2 review, 2026-07-22 — superseded 2026-07-23)¶

    The original hazard note prescribed cutting 0.24.0 strictly from a clean step1 checkout because the second wave (0088/0089/0090 + geometry contract) was uncommitted and UNREVIEWED at the time. That precondition no longer holds: the wave subsequently passed three adversarial review cycles plus a final verification gate (1413 tests, lint clean, cross-repo passthrough re-verified), and the owner directed that all work from this cycle ship together. Decision: 0.24.0 ships the full tree (step1 + step2 + the reviewed working-tree wave). Consequences of the fold, addressed deliberately: 1. matplotlib moving to the concept extra ships in 0.24.0 as a documented packaging change (CHANGELOG "Import diet" entry), not as a silent lock drift. 2. The second-wave subsection stays in the 0.24.0 notes because it ships in 0.24.0; no [Unreleased] hoist. The former "0.25-track" label was renamed to a neutral heading. 3. Smoke evidence (a) compares 0.23.1 vs the full tree on RAW YUV planes, which is robust to the new x264 VUI color tags by construction (pixel-identical is the claim under test; container bytes are not).

    Smoke evidence (recorded 2026-07-23, TI2V-5B q8, 384x384, 9 frames, 2 steps, seed 42)¶

    • (a) Same-seed output identity vs 0.23.1: PASSED in the honest form. The 0.23.1 release commit (worktree 1e3258b, identical locked deps: torch 2.9.1 / transformers 5.0.0) and the full 0.24.0 tree produced 9/9 bitwise-identical frames on raw YUV planes. This simultaneously re-proves the video-writer color-tag change preserves coded pixels (old writer vs new writer, same bits). A FIRST comparison against the PyPI 0.23.1 install in a different dependency set (torch 2.8.0 / transformers 5.8.0) DIFFERED (mean luma delta ~10): root-caused to UMT5 kernel numerics across torch/transformers versions, not to mlx-gen code — pinned by a probe showing numpy-vs-torch tokenization and encoding are bitwise identical within one environment (ids, masks, embeds), and by a step-level bisect (step1 == full tree == 0.23.1-same-env, all bitwise). Embedding hosts should expect same-seed output shifts when THEIR torch/transformers versions change; that is upstream-kernel behavior, not an mlx-gen contract.
    • (b) Disk-cache hit vs miss: bitwise identical (raw YUV, 9/9 frames). Hit runs skip the UMT5 load entirely (cache-hit end-to-end run: ~27 s vs ~4 min miss on a contended GPU).
    • (c) --no-validate-health: exit 0, output bitwise identical to the default run, sidecar records health_check: "skipped"; --json-events start event carries resolved width/height (observed live).
    • (d) MFLUX_RUN_LOCAL_WAN_PARITY=1 local parity suite: 6/6 passed (Wan-AI/Wan2.2-TI2V-5B-Diffusers fixtures).
